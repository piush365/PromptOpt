# Category templates

Generated by `python -m app.templates_doc` from the Stage B rule constants (`backend/app/stage_b/rules.py`); do not edit by hand. Stage B adds these only when the prompt does not already state them, and only when the category is reliable (Stage A confidence >= 0.6, or chosen by the user). Below the gate, B08 adds the text-group template when closed_qa + information_extraction + summarization together reach it and text is attached: `Answer from the provided text in at most three sentences.`. Otherwise the prompt goes to Stage C for the category.

Every category also gets the clean-up rules (B07 structure, B01 filler, B02 repetition) and, with an attachment, the attachment rule for its type (B09-B15).

| category | output format (B03) | length (B04) | other | constraints Stage A checks |
|---|---|---|---|---|
| closed_qa | Start with the direct answer. | Answer in at most two sentences. | - | length |
| information_extraction | List each extracted item on its own line; if the text does not contain it, reply "Not found". | - | - | - |
| classification | For each item, output "item: label" on its own line. | - | B06 states the allowed labels it finds in the prompt (`Use only these labels: "x", "y".`); a "which of these ... are X" question gets `"yes", "no"`; otherwise the label set is recorded as unresolved. A yes/no question about one item gets `Output only the label.` instead of the per-item format. | - |
| summarization | Use bullet points. | Keep it under 100 words. | - | length, audience, tone |
| coding | Return only the code, in a single code block. | - | B05: no language named -> `Use Python.`; code supplied or attached -> `Keep the language of the given code.` | language |
